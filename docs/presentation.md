### Слайд 2. Проблема и цель

**Проблема:**
- Аудитория: люди с нарушениями слуха
- Обычные платформы используют звуковые уведомления и голосовой контакт
- Нет доступных решений для организации мероприятий

**Цель:**
Платформа с визуальными уведомлениями, читаемыми бейджами статусов и отсутствием зависимости от звука.

---

### Слайд 3. Требования и стейкхолдеры

- Ключевые функциональные требования: регистрация с ролью, создание инклюзивных мероприятий, запись на события, визуальные уведомления
- Нефункциональные требования: **соответствие WCAG 2.1 AA** — стандарт доступности веб-интерфейсов
- Главный стейкхолдер: **участник с нарушением слуха**
- User Stories реализованы в docs/requirements.md

---

### Слайд 4. Архитектура и БД

**Трёхслойная архитектура:**
- Клиент: HTML5, CSS3, JavaScript, Jinja2
- Сервер: Flask + JWT-авторизация
- Данные: SQLAlchemy ORM (SQLite локально, PostgreSQL в продакшене)

**Модели БД:** User, Event, Registration

**Роли:** user, organizer, admin

**Безопасность:** хеширование паролей, JWT-токены, декораторы `@token_required` и `@role_required`

---

### Слайд 5. Демонстрация

Сквозной сценарий:
1. Регистрация организатора
2. Создание инклюзивного мероприятия
3. Регистрация участника с отметкой «слабослышащий»
4. Запись на мероприятие → статус pending
5. Визуальное уведомление без звукового сигнала
